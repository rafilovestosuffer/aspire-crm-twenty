01 What this is

Aspire's CRM is moving off GoHighLevel onto software we run ourselves: Twenty for the CRM — contacts, companies, pipeline, and a data model shaped like our actual business — and n8n for automation: forms, lead routing, renewal chasing, email, alerting.

Both are open source. Both run on one server. The data lives in our own database. The build is scripted end to end: one command takes an empty machine to a working CRM with the automation running and verified.

02 Why move

GoHighLevel cannot model this business. It has contacts and it has "deals". We sell recurring SOC subscriptions, CMMC engagements with audit dates, and training accounts with seat counts and phishing scores tracked over quarters. In GoHighLevel all of that flattens into custom fields on a deal. Here they are real objects with real relationships — so "which subscriptions renew in the next 90 days, and how are their seats tracking" is a saved view, not a spreadsheet export.

GoHighLevel hides its own automation history. No API exposes what a workflow did, or whether it failed. That gap is what made this audit hard, and it is why every automation here writes an automationRun record back into the CRM. Every run, success and failure, is queryable.

We are a security company. Client data in a marketing SaaS is a harder conversation than client data on infrastructure we control, patch and back up.

04 What "proven" means

Deployed is not working. These workflows sat in n8n for weeks looking correct and were completely broken — filters the CRM silently ignored, an error handler wired to a name that resolved to nothing, consent records created with no person attached. All of it looked fine in the editor.

So the verification does not check that workflows exist. It submits the real form, follows the real redirect, breaks something on purpose, triggers the real schedules, and then asks the CRM whether the records are there.

ProvesCheck
Lead capturePerson, company, linked consent, scored task, acknowledgement to the right address
Consent enforcementNon-consenting contact → send refused, no mail, refusal logged with its reason
Click trackingRedirect to the destination, click counted
Failure handlingA deliberate failure produces a FAILED record carrying the real error, and a delivered alert
Scheduled workRenewals and sweeps run clean against the seeded data

Run it any time. If something breaks later, it says so.

Nothing is "built but never run." That is the sentence that matters. The dangerous category in any migration is code that exists, looks finished, and has never executed. It is empty here.

The 33 deferred are mostly telephony — SMS, voice, IVR, call recording, which need a licensed carrier and which we barely use — plus website and funnel hosting (aspiretss.com stays where it is) and course delivery (aspireelearning.com already does it). They are not gaps; they are decisions.

Unrecoverable if missed

The consent list does not come back. GoHighLevel's suppression list — everyone who has unsubscribed or bounced — is lost when the account terminates. Export it and reconcile the count exactly before any termination date is agreed. Emailing someone who opted out is a compliance incident, and we sell compliance.

Not yet true

No backup here has ever been restored. Backups run nightly, but an untested backup is not a backup. Restoring one into a scratch database, and recording the date, is a Phase 5 gate — not a nice-to-have. Keep GoHighLevel read-only for 30–60 days after cutover.

08 Running it

Docker, 6 GB of free RAM, Python 3.9+.

git clone https://github.com/rafilovestosuffer/aspire-crm-twenty.git
cd aspire-crm-twenty
./infra/rebuild.sh

Eleven gated steps, about twelve minutes, stopping at the first failure: stack up → verify every layer → create the workspace → object model → demo data → credentials → validate every CRM API call against the live schema → deploy and activate → run the workflows and check what they did → verify every layer again.

Nothing leaves the machine. Email goes to a local catcher, so the send path runs for real with no mail account and no chance of reaching a live contact.

Before anything else

Back up ENCRYPTION_KEY and N8N_ENCRYPTION_KEY somewhere other than the laptop. Lose the first and every secret the CRM holds becomes permanently unreadable. There is no recovery path. Change the default login before the machine is on a shared network.

Moving to the company server

The laptop stack and the server stack are the same files — nothing is thrown away and nothing is untested at cutover. The server overlay binds both ports to loopback so only the reverse proxy reaches them; set the real hostnames, point alerts at the real chat webhook, and terminate TLS at the proxy. Several features require a secure context.

09 The demo, in ten minutes

Order matters. Lead with the data model, land on the live form.

  • A company record — people, subscription, compliance engagement, training account, phishing trend. "GoHighLevel can't model any of this. It forces everything into a deal."
  • Renewals in the next 90 days, the pipeline, seats near capacity. "Renewal exposure and upsell signals, both one click."
  • A contact timeline with a real email thread and calendar event. "This is where the inbox went. Native, syncs every five minutes."
  • Fill the public form live on screen. The person appears scored and assigned, a task is raised, the acknowledgement sends. "That form is hosted by our own stack. No third-party tool."
  • Try to send to an opted-out contact. It refuses and logs why. "This is the control we tell clients to implement."
  • Run the renewal escalation. "GoHighLevel cannot do this — it has no subscription object."
  • The automation-run view. "Every run, success and failure. GoHighLevel exposes no execution history at all — that gap is what made the audit hard."

Watching a record appear from a form submission does more than any document.

10 Hard questions

Is this a hobby project that will break?

Every claim here is produced by a script that runs against the live system. The build has three gates: the workflow generator refuses to emit code that would fail at runtime, a validator checks all 28 CRM API calls against the live schema, and 25 checks exercise the real paths. Together they caught more than twenty defects — several of which would have been silent in production.

What happens when Rafi is on holiday?

Today, that is a real risk. It is a Phase 5 gate: a runbook plus a second named operator who has completed one task from it unaided. Do not skip it.

What if Twenty disappears?

The data is in our own database and can be dumped to CSV or SQL at any time. That is strictly better than the current position, where the data is in someone else's SaaS.

Why not just keep GoHighLevel?

Because it cannot model subscriptions, compliance engagements or training seats; because it will not tell us what its own automation did; and because it costs a recurring fee for a system we cannot inspect. The replacement runs on one server.
